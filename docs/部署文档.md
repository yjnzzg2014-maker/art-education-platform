## 1. 平台架构概览

```
                    ┌─────────────────────────────────────────┐
                    │              Nginx 反向代理               │
                    │  :80 / :443                              │
                    └──────┬──────────────────┬────────────────┘
                           │                  │
              ┌────────────▼───────┐  ┌───────▼────────────┐
              │    创作端 (meishu)   │  │   分析端 (meishu2)  │
              │    端口: 2500       │  │   API:  8085       │
              │                    │  │   前端: 8086 (开发)  │
              │  Express+Socket.IO │  │  Express + React    │
              │  静态 HTML 前端     │  │  JWT 认证           │
              └────────┬───────────┘  └───────┬────────────┘
                       │                      │
                       │   ┌──────────────┐   │
                       └──►│  artedu.db   │◄──┘
                           │  (SQLite)    │
                           └──────────────┘
```

| 服务 | 说明 | 默认端口 | 前端 |
|------|------|----------|------|
| **创作端** (meishu) | 课堂实时创作工具，Socket.IO 实时通信 | 2500 | 静态 HTML，无需构建 |
| **分析端** (meishu2) | AI 智能分析平台，JWT 认证 | API 8085 / 前端 8086 | React + Vite，需要构建 |

两端通过 **同一个 SQLite 数据库文件** (`artedu.db`) 共享学生、班级、作品等数据。

## 3. 快速开始（本地开发）

### 3.1 安装 Node.js

如果尚未安装 Node.js，推荐使用 nvm（Node 版本管理器）：

```bash
# macOS / Linux
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc   # 或 source ~/.zshrc
nvm install 22
nvm use 22

# 验证安装
node --version   # 应显示 v22.x.x
npm --version    # 应显示 10.x.x
```

Windows 用户可从 [Node.js 官网](https://nodejs.org/) 下载安装包。

### 3.2 获取代码

```bash
# 假设两个项目放在同一个父目录下
mkdir -p ~/projects && cd ~/projects

git clone <你的仓库地址>/meishu.git
git clone <你的仓库地址>/meishu2.git
```

最终目录结构：

```
~/projects/
├── meishu/                  # 创作端
└── meishu2/
    └── art-edu-platform/    # 分析端
```

### 3.3 启动创作端

```bash
cd ~/projects/meishu

# 安装依赖
npm install

# 启动服务器
node server.js
```

启动成功后会看到：

```
[db] Database ready: /path/to/meishu/data/artedu.db
Sun Decorator server running on http://localhost:2500
```

打开浏览器访问：
- 学生端: `http://localhost:2500/student.html`
- 教师端: `http://localhost:2500/teacher.html`

### 3.4 启动分析端

```bash
cd ~/projects/meishu2/art-edu-platform

# 安装依赖
npm install

# 复制环境变量配置文件
cp .env.example .env
```

编辑 `.env` 文件，**必须设置 JWT_SECRET**：

```bash
# 生成随机密钥（在终端执行）
openssl rand -base64 32
```

将生成的字符串填入 `.env`：

```env
JWT_SECRET=你生成的随机字符串
PORT=8085
```

启动开发服务器：

```bash
npm run dev
```

启动成功后会看到：

```
Art Education API Server running on http://127.0.0.1:8085
  VITE v8.x.x  ready in xxx ms
  ➜  Local:   http://localhost:8086/
```

打开浏览器访问 `http://localhost:8086`，使用默认账户登录：

| 账户 | 用户名 | 密码 |
|------|--------|------|
| 管理员 | `admin` | `admin123` |
| 教师 | `teacher` | `teacher123` |

> **注意**：开发模式下会自动创建种子数据（44 名学生、示例作品）。生产模式（`NODE_ENV=production`）不会插入种子数据。

## 4. 环境变量说明

### 4.1 分析端环境变量（meishu2/art-edu-platform/.env）

| 变量名 | 必填 | 默认值 | 说明 |
|--------|------|--------|------|
| `JWT_SECRET` | **是** | 无 | JWT 签名密钥，不设置则服务无法启动。生产环境务必使用强随机字符串 |
| `PORT` | 否 | `8085` | API 服务监听端口 |
| `HOST` | 否 | `127.0.0.1` | API 服务监听地址。设为 `0.0.0.0` 允许外部访问 |
| `ALLOWED_ORIGIN` | 否 | `http://localhost:8086` | CORS 允许的前端来源地址。生产环境需改为实际域名 |
| `NODE_ENV` | 否 | 无 | 设为 `production` 跳过种子数据插入 |
| `MINIMAX_API_KEY` | 否 | 空 | MiniMax 视觉大模型 API Key。不填则使用 Mock 模式（随机评分） |

`.env` 文件完整示例：

```env
# === 必填 ===
JWT_SECRET=aB3dE6gH9jK2mN5pQ8rS1uV4wX7yZ0cF

# === 可选 ===
PORT=8085
HOST=0.0.0.0
ALLOWED_ORIGIN=https://art.yourschool.edu.cn
NODE_ENV=production
MINIMAX_API_KEY=your-minimax-api-key-here
```

### 4.2 创作端环境变量（meishu/.env.local）

创作端的核心服务不依赖环境变量，仅端口和 OSS 上传功能使用：

| 变量名 | 必填 | 默认值 | 说明 |
|--------|------|--------|------|
| `PORT` | 否 | `2500` | 服务监听端口 |
| `OSS_ACCESS_KEY_ID` | 否 | 空 | 阿里云 OSS AccessKey ID（仅 CDN 打包上传时需要） |
| `OSS_ACCESS_KEY_SECRET` | 否 | 空 | 阿里云 OSS AccessKey Secret |
| `OSS_REGION` | 否 | `oss-cn-hangzhou` | OSS 区域 |
| `OSS_BUCKET` | 否 | 空 | OSS Bucket 名称 |
| `OSS_CDN_DOMAIN` | 否 | 空 | CDN 加速域名 |

> **说明**：OSS 相关变量仅在执行 `npm run upload`（打包上传到 CDN）时需要，本地开发和局域网部署不需要配置。

## 5. 双端联合部署（共享数据库）

两端各自维护一份 SQLite 数据库文件，使用相同的表结构。要实现数据共享，需要让两端指向同一个数据库文件。

### 5.1 数据库文件位置

| 服务 | 默认数据库路径 |
|------|---------------|
| 创作端 | `meishu/data/artedu.db` |
| 分析端 | `meishu2/art-edu-platform/server/artedu.db` |

### 5.2 方案一：软链接（推荐）

选择一个作为"主数据库"，另一端创建软链接指向它。推荐以分析端的数据库为主，因为它包含更完整的表结构和迁移机制。

```bash
# 1. 确保分析端已启动过一次（自动建库建表）
cd ~/projects/meishu2/art-edu-platform
npm run server
# 等待看到 "Database initialization complete" 后 Ctrl+C 停止

# 2. 备份创作端原有数据库（如果有）
cd ~/projects/meishu
mv data/artedu.db data/artedu.db.bak 2>/dev/null

# 3. 创建软链接，让创作端指向分析端数据库
ln -s ~/projects/meishu2/art-edu-platform/server/artedu.db ~/projects/meishu/data/artedu.db

# 4. 验证链接
ls -la ~/projects/meishu/data/artedu.db
# 应显示 -> ~/projects/meishu2/art-edu-platform/server/artedu.db
```

### 5.3 方案二：统一到外部路径

将数据库文件放到两个项目之外的公共位置，两端都创建软链接指向它。

```bash
# 1. 创建公共数据目录
mkdir -p /opt/artedu/data

# 2. 如果已有数据，先移动
mv ~/projects/meishu2/art-edu-platform/server/artedu.db /opt/artedu/data/

# 3. 两端各自创建软链接
ln -s /opt/artedu/data/artedu.db ~/projects/meishu/data/artedu.db
ln -s /opt/artedu/data/artedu.db ~/projects/meishu2/art-edu-platform/server/artedu.db

# 4. WAL 模式相关文件也会自动在同目录生成，无需额外处理
```

### 5.4 并发访问注意事项

SQLite 使用 WAL（Write-Ahead Logging）模式运行，支持一写多读。两端同时运行时：

- **读操作**：完全并发，无冲突
- **写操作**：SQLite 内部会排队处理，对于小学场景的并发量完全够用
- **不要**将数据库文件放在网络挂载盘（NFS/SMB）上，SQLite 不支持跨网络文件锁

> **重要**：两端使用不同的 SQLite 驱动（创作端用 `better-sqlite3` 同步驱动，分析端用 `sqlite3` 异步驱动），但它们都兼容同一个 SQLite 数据库文件。

## 6. 生产部署

### 6.1 安装 PM2

PM2 是 Node.js 进程管理器，支持自动重启、日志管理和开机启动。

```bash
npm install -g pm2
```

### 6.2 构建分析端前端

分析端的 React 前端需要构建为静态文件：

```bash
cd ~/projects/meishu2/art-edu-platform

# 安装依赖
npm install

# 构建前端
npm run build
```

构建产物输出到 `dist/` 目录。分析端的 Express 服务器已配置为提供 `public/` 目录下的静态文件，需要将构建产物复制过去：

```bash
# 将构建产物复制到 public 目录供 Express 服务
rm -rf public
cp -r dist public
```

### 6.3 创建 PM2 配置文件

在项目根目录（两个项目的父目录）创建 `ecosystem.config.cjs`：

```bash
cd ~/projects
```

创建文件 `ecosystem.config.cjs`，内容如下：

```javascript
module.exports = {
  apps: [
    {
      name: 'artedu-creation',
      cwd: './meishu',
      script: 'server.js',
      env: {
        PORT: 2500,
        NODE_ENV: 'production'
      },
      instances: 1,
      autorestart: true,
      max_memory_restart: '500M',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
      error_file: './logs/creation-error.log',
      out_file: './logs/creation-out.log',
      merge_logs: true
    },
    {
      name: 'artedu-analysis',
      cwd: './meishu2/art-edu-platform',
      script: 'server/index.js',
      env: {
        PORT: 8085,
        HOST: '127.0.0.1',
        NODE_ENV: 'production',
        JWT_SECRET: '替换为你的强随机字符串',
        ALLOWED_ORIGIN: 'https://art.yourschool.edu.cn'
      },
      instances: 1,
      autorestart: true,
      max_memory_restart: '1G',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
      error_file: './logs/analysis-error.log',
      out_file: './logs/analysis-out.log',
      merge_logs: true
    }
  ]
};
```

### 6.4 启动服务

```bash
# 创建日志目录
mkdir -p ~/projects/logs

# 启动所有服务
pm2 start ecosystem.config.cjs

# 查看运行状态
pm2 status

# 查看日志
pm2 logs                        # 查看所有服务日志
pm2 logs artedu-creation        # 仅创作端日志
pm2 logs artedu-analysis        # 仅分析端日志

# 设置开机自启
pm2 startup
pm2 save
```

### 6.5 PM2 常用命令

```bash
pm2 status                      # 查看所有进程状态
pm2 restart all                 # 重启所有服务
pm2 restart artedu-creation     # 重启创作端
pm2 restart artedu-analysis     # 重启分析端
pm2 stop all                    # 停止所有服务
pm2 delete all                  # 删除所有进程
pm2 monit                       # 实时监控面板
```

### 6.6 systemd 方式（替代 PM2）

如果不使用 PM2，也可以使用 systemd 管理服务。

创建创作端服务文件 `/etc/systemd/system/artedu-creation.service`：

```ini
[Unit]
Description=Art Education Platform - Creation Service
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/home/deploy/projects/meishu
ExecStart=/usr/bin/node server.js
Environment=PORT=2500
Environment=NODE_ENV=production
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

创建分析端服务文件 `/etc/systemd/system/artedu-analysis.service`：

```ini
[Unit]
Description=Art Education Platform - Analysis Service
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/home/deploy/projects/meishu2/art-edu-platform
ExecStart=/usr/bin/node server/index.js
Environment=PORT=8085
Environment=HOST=127.0.0.1
Environment=NODE_ENV=production
Environment=JWT_SECRET=替换为你的强随机字符串
Environment=ALLOWED_ORIGIN=https://art.yourschool.edu.cn
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

启用并启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable artedu-creation artedu-analysis
sudo systemctl start artedu-creation artedu-analysis

# 查看状态
sudo systemctl status artedu-creation
sudo systemctl status artedu-analysis

# 查看日志
sudo journalctl -u artedu-creation -f
sudo journalctl -u artedu-analysis -f
```

## 7. Nginx 反向代理配置

Nginx 做反向代理有三个作用：统一入口端口（80/443）、提供 SSL 终止、处理静态文件缓存。

### 7.1 安装 Nginx

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install -y nginx

# macOS (Homebrew)
brew install nginx
```

### 7.2 配置文件

创建配置文件 `/etc/nginx/sites-available/artedu`：

```nginx
# ========================================
# 创作端 - 课堂实时创作
# ========================================
server {
    listen 80;
    server_name create.yourschool.edu.cn;    # 替换为你的域名

    # 安全头
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;

    # 请求体大小限制（图片上传）
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:2500;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Socket.IO 支持（必须配置）
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Socket.IO 超时设置
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}

# ========================================
# 分析端 - AI 智能分析平台
# ========================================
server {
    listen 80;
    server_name art.yourschool.edu.cn;       # 替换为你的域名

    # 安全头
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;

    # 请求体大小限制（批量上传作品图片）
    client_max_body_size 50m;

    # 前端静态文件（构建产物）
    root /home/deploy/projects/meishu2/art-edu-platform/dist;
    index index.html;

    # API 请求代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:8085;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # React Router - 所有非 API、非静态文件请求返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 7.3 仅使用 IP 地址（无域名）

如果没有域名，在学校局域网内使用 IP 地址访问，修改 `server_name` 为服务器 IP，并用不同端口区分两端：

```nginx
# 创作端 - 端口 80
server {
    listen 80;
    server_name _;

    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:2500;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400s;
    }
}

# 分析端 - 端口 8080
server {
    listen 8080;
    server_name _;

    client_max_body_size 50m;
    root /home/deploy/projects/meishu2/art-edu-platform/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8085;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

这样访问方式为：
- 创作端: `http://<your-server-ip>/student.html`
- 分析端: `http://<your-server-ip>:8080`

### 7.4 启用配置

```bash
# 创建符号链接启用配置
sudo ln -s /etc/nginx/sites-available/artedu /etc/nginx/sites-enabled/

# 删除默认配置（可选）
sudo rm /etc/nginx/sites-enabled/default

# 测试配置语法
sudo nginx -t

# 重载配置
sudo systemctl reload nginx
```

## 8. SSL 证书配置

### 8.1 使用 Let's Encrypt（免费，推荐）

需要有公网域名并且 DNS 已解析到服务器 IP。

```bash
# 安装 Certbot
sudo apt install -y certbot python3-certbot-nginx

# 自动申请并配置 SSL（会自动修改 Nginx 配置）
sudo certbot --nginx -d create.yourschool.edu.cn -d art.yourschool.edu.cn

# 验证自动续期
sudo certbot renew --dry-run
```

Certbot 会自动将 Nginx 配置从 `listen 80` 改为 `listen 443 ssl`，并添加 80 到 443 的重定向。

### 8.2 使用自签名证书（内网/测试用）

```bash
# 生成自签名证书（有效期 365 天）
sudo mkdir -p /etc/nginx/ssl
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/artedu.key \
  -out /etc/nginx/ssl/artedu.crt \
  -subj "/CN=art.yourschool.edu.cn"
```

在 Nginx 配置的 `server` 块中添加：

```nginx
server {
    listen 443 ssl;
    server_name art.yourschool.edu.cn;

    ssl_certificate /etc/nginx/ssl/artedu.crt;
    ssl_certificate_key /etc/nginx/ssl/artedu.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    # ... 其余配置不变
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name art.yourschool.edu.cn;
    return 301 https://$host$request_uri;
}
```

> **注意**：自签名证书会导致浏览器提示"不安全"，需要手动信任。校园局域网可以通过组策略将证书推送到学生机器。

## 9. 数据备份与恢复

### 9.1 手动备份

SQLite 数据库是单个文件，备份非常简单。但需要注意 WAL 模式下有额外的 `-wal` 和 `-shm` 文件。

```bash
# 推荐方式：使用 sqlite3 命令行工具进行安全备份
# 这会将 WAL 日志合并到主数据库文件
sqlite3 /path/to/artedu.db "VACUUM INTO '/path/to/backup/artedu-$(date +%Y%m%d-%H%M%S).db'"
```

如果没有安装 sqlite3 命令行工具，也可以直接复制文件（建议先停止服务）：

```bash
# 停止服务
pm2 stop all

# 复制数据库文件（三个文件都要复制）
cp /path/to/artedu.db /path/to/backup/
cp /path/to/artedu.db-wal /path/to/backup/ 2>/dev/null
cp /path/to/artedu.db-shm /path/to/backup/ 2>/dev/null

# 重启服务
pm2 start all
```

### 9.2 自动定时备份（cron）

```bash
# 编辑 crontab
crontab -e

# 添加以下行：每天凌晨 2 点备份，保留最近 30 天
0 2 * * * sqlite3 /home/deploy/projects/meishu2/art-edu-platform/server/artedu.db "VACUUM INTO '/home/deploy/backups/artedu-$(date +\%Y\%m\%d).db'" && find /home/deploy/backups -name "artedu-*.db" -mtime +30 -delete
```

### 9.3 恢复数据

```bash
# 停止服务
pm2 stop all

# 用备份文件替换当前数据库
cp /path/to/backup/artedu-20260515.db /path/to/artedu.db

# 重启服务
pm2 start all
```

别忘了同时备份上传的作品图片（`meishu2/art-edu-platform/uploads/` 目录）。

## 10. 常见问题排查

### 问题 1：分析端启动报 "FATAL: JWT_SECRET environment variable is not set"

**原因**：未配置 JWT_SECRET 环境变量。分析端强制要求此变量。

**解决**：

```bash
# 生成随机密钥
openssl rand -base64 32

# 编辑 .env 文件
cd ~/projects/meishu2/art-edu-platform
nano .env
# 添加：JWT_SECRET=生成的字符串
```

---

### 问题 2：浏览器打开分析端显示白屏

**可能原因 1**：前端未构建（生产环境）。

```bash
cd ~/projects/meishu2/art-edu-platform
npm run build
cp -r dist public
```

**可能原因 2**：Nginx 的 `try_files` 未配置，React Router 的路由无法正确回退到 `index.html`。确认 Nginx 配置中有：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

---

### 问题 3：创作端 Socket.IO 连接失败（学生页面加载后无法操作）

**原因**：Nginx 未正确配置 WebSocket 代理。

**解决**：确认 Nginx 配置中创作端的 `location /` 块包含以下行：

```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 86400s;
```

修改后重载 Nginx：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

---

### 问题 4：两端数据不同步

**检查清单**：

```bash
# 1. 确认软链接是否正确
ls -la ~/projects/meishu/data/artedu.db
# 应显示 -> 指向分析端的数据库路径

# 2. 确认两端读取的是同一个文件
# 创作端日志会显示：
# [db] Database ready: /path/to/meishu/data/artedu.db
# 分析端日志会显示：
# Database connected: /path/to/meishu2/art-edu-platform/server/artedu.db

# 3. 确认文件权限
ls -la /path/to/artedu.db
# 运行服务的用户需要对数据库文件有读写权限
```

---

### 问题 5：npm install 安装失败，报 node-gyp 或 better-sqlite3 编译错误

**原因**：`better-sqlite3`（创作端使用）和 `sharp`（图片处理）需要编译原生 C++ 模块。

**解决**：

```bash
# Ubuntu / Debian - 安装编译工具
sudo apt install -y build-essential python3

# macOS - 安装 Xcode 命令行工具
xcode-select --install
```

如果 `sharp` 安装仍然失败：

```bash
npm install --platform=linux --arch=x64 sharp
# 或清除缓存重试
npm cache clean --force
npm install
```

---

### 问题 6：MiniMax AI 分析不工作，评分结果都是随机数

**原因**：未配置 `MINIMAX_API_KEY`，系统运行在 Mock 模式。

**说明**：这是正常的降级行为。如果需要真实 AI 分析：

1. 访问 [MiniMax 开放平台](https://www.minimaxi.com/) 注册并获取 API Key
2. 将 Key 填入 `.env` 文件的 `MINIMAX_API_KEY` 字段
3. 或者在分析端 Web 界面的"设置"中直接填入 API Key（保存在数据库中，优先级高于环境变量）

---

### 问题 7：上传图片失败，提示文件过大

**原因**：上传大小限制在多个层面。

**检查清单**：

1. **Nginx 层**：确认 `client_max_body_size` 设置够大（建议 `50m`）
2. **Express 层**：分析端 JSON body 限制为 1MB（`express.json({ limit: '1mb' })`），图片上传走 multer 不受此限制
3. **multer 层**：单文件限制（代码中配置），批量上传最多 20 张

---

### 问题 8：端口被占用

```bash
# 查看哪个进程占用了端口
lsof -i :2500    # 创作端端口
lsof -i :8085    # 分析端 API 端口

# 终止占用进程（替换 PID）
kill <PID>

# 或者修改端口：
# 创作端：设置环境变量 PORT=2501 node server.js
# 分析端：修改 .env 中的 PORT=8086
```

---

### 问题 9：生产环境登录后提示未授权

**可能原因**：`ALLOWED_ORIGIN` 配置不正确，CORS 拒绝了前端请求。

**解决**：确保 `.env` 中的 `ALLOWED_ORIGIN` 与浏览器地址栏中的地址完全一致（包括协议和端口）：

```env
# 错误示例
ALLOWED_ORIGIN=http://art.school.cn      # 实际用 https 访问
ALLOWED_ORIGIN=https://art.school.cn:80  # 多余的端口号

# 正确示例
ALLOWED_ORIGIN=https://art.school.cn
```

---

### 问题 10：数据库被锁（database is locked）

**原因**：SQLite 在高并发写入时可能出现锁竞争。

**解决**：

1. 确认 WAL 模式已启用（两端代码中已默认开启）
2. 确认数据库不在网络挂载盘上
3. 如果频繁出现，考虑错开两端的写入密集操作（如批量分析时暂停创作端提交）

```bash
# 检查 WAL 模式是否生效
sqlite3 /path/to/artedu.db "PRAGMA journal_mode;"
# 应输出: wal
```
